# MindMap (native editor prototype)

Build on macOS with Swift command-line tools: `bash build.sh`. Run with `open build/MindMap.app`.
No Xcode project, third-party dependencies, signing, or original application are required.

- A native toolbar is wired to New Main Node, New Child, New Sibling, Fold/Unfold, Fit Map, Show/Hide Outline, Undo and Redo; Fit Map reuses the same viewport-fit action used at launch and after successful document opens. An isolated visible/key native App AX-pressed its uniquely identified New Child toolbar button, confirming one selected child, a dirty title and native editing focus; the user also reported the sidebar/toolbar working in the earlier preview, but the new build's other toolbar buttons remain unverified by Agent GUI automation. The native Node menu exposes creation and detach commands. Tab: new child (or the first root when an opened map is empty); plain Return in the text field commits and exits editing, then Return on the canvas makes a sibling; Command-N: new main/root node; Option-Return: new sibling before; Option-Tab: insert a parent; Shift-Return on the canvas: another main/root node. Ordinary sibling/parent insertion does nothing on roots (menu items are not yet disabled contextually).
- A native 180–320 pt outline sidebar shares the canvas tree, selected node, fold state and undo; View → Show/Hide Outline (Option-Command-S), or the persistent toolbar button, collapses/restores it; hiding moves keyboard focus back to the canvas. Right-clicking an outline row or canvas node offers shared native node actions; right-clicking blank space offers New Main Node. Selecting a row commits any active canvas edit first; successful document opens refresh the outline. Plain Return/Enter on a selected outline row uses the canvas editor; one isolated visible/key native App with the actual Node menu installed confirmed local Return edits the same node without adding a sibling. System VoiceOver and full sidebar keyboard behavior remain unverified.
- Type to edit the selected node through a native text field; double-click to replace its text, Escape to cancel editing. An owned visible/key window passed native marked-text injection; physical Chinese IME candidate-window behavior remains unverified.
- Arrow keys: navigate visible nodes; Command-Up/Down: move the selected node among siblings; Command-Shift-D: detach the selected non-root node into a main/root node; Delete: remove a non-root node or an extra main root (the last root is protected); Option+period or Space: fold/unfold while the canvas has focus. While editing text, punctuation remains text input.
- Command-Z / Shift-Command-Z: model undo/redo. Drag empty canvas or the root to pan. Drag a **non-root** node at least 9 screen points: it and its visible descendants follow the grab point; over valid node/child-gap targets, siblings elastically make room without changing the real tree until mouse-up (or move immediately when macOS Reduce Motion is enabled). A center-parent drop emphasizes its underline and endpoint; invalid release or Escape restores the original map. Pinch or Option-scroll to zoom. The user physically checked the previous live-reflow preview on 2026-10-23: dragged subtrees and real-time sibling displacement basically worked, but elasticity and inertia were missing. In the new preview, displaced siblings spring toward the valid preview while the dragged subtree stays pointer-locked; owned visible/key synthetic tests cover the spring and AX geometry. The user confirmed the earlier preview gained elasticity but reported unwanted near-sibling attraction and a missing first-level drag connector. The repulsion preview keeps that original-parent line visible, repels nearby stationary child branches (including their descendants) without moving the dragged subtree off the pointer, and requires at least 65% invisible node hit-area overlap for center-hover reparenting; the user physically tested it on 2026-10-23 and reported no problems with those interactions. Root reordering, free-position dragging and release inertia are not implemented.
- Drawn nodes appear as labeled, selected-state accessibility buttons; press one to select and edit using the native text field. Their cached accessibility frames use the same live drag layout as the canvas, with layout-change notifications in an attached window; native VoiceOver has not been physically checked. Root labels use 20pt and branches 16pt Songti SC where installed, with a system-font fallback; layout, line-aligned drawing and borderless inline editing share those metrics. In the newest preview, main/root nodes have a single persistent rounded rectangle and only child labels remain on lines without cards; selected nodes highlight a text-only box while preserving their original branch-line color; drag targets still emphasize the candidate connection. The node context menu's Node Width offers Auto/170/240/320/480 pt presets plus a Custom Width dialog, and dragging the selected text box's top-right circular handle continuously resizes that node from 60 to 1000 pt while its left edge stays fixed; one drag creates one undo step and custom widths survive own `.mindmap.json` Save/Open. Old JSON without a width keeps content-based wrapping and a 320 pt default cap. Editing zooms to at least 0.8 when needed so the readable native field remains within the invisible node hit region; after editing ends, using Fit Map can return to lower zoom. View → Appearance offers persisted System (default), Light and Dark choices through native AppKit colors. A newly staged visible/key native App validated View → Appearance actions and checkmarks with isolated preferences plus canvas light/dark snapshots, not external menu clicks; the user subsequently reported zoomed editing fully working and the appearance excellent; system VoiceOver and separate candidate-window specifics remain unrecorded.
- File → Open Own JSON… (⌘O) opens editable `.mindmap.json` (a JSON array of roots); File → Open MindNode (Read-only)… (⇧⌘O) imports supported `.mindnode` directory packages or regular v9 binary-plist files. The MindNode picker keeps folders navigable, enables `.mindnode` directory packages and regular files while disabling unrelated files, and validates the chosen entry before accepting it. Both forms must contain the known v9 binary plist schema: `contents.xml` inside a directory, or the bytes of the regular file itself. Small ZIP archives receive an explicit unsupported-container alert; any document over 8 MiB is rejected before format inspection. The user then authorized read-only inspection of one specifically named original; its independently checked private copy is a v9 directory package with 4 maps and 65 nodes. The first failure was a legitimate child with an empty `title.text` string, which the old XML-only title parser rejected. A synthetic RED→GREEN test now covers that case, and the exact private copy imports via the Swift CLI; the source was not changed. The user independently opened this authorized document in the earlier preview; the visual changes in this new ZIP have not been accepted by the user or independently passed a visible/key native window check (desktop focus switched during that check). A private copy was opened in original MindNode strictly for visual comparison, with no document edits. Newer and compressed formats remain unsupported. Text, tree structure and fold state are imported, and every one of the 65 nodes in the authorized copy supplies its original branch RGBA/line width for display (not full text/root-shape styling). Notes, attachments, styles and original `.mindnode` saving are **not** round-tripped. The source package is never edited. Save prompts for a **new** `.mindmap.json` after an import, even if another JSON file was previously open; subsequent saves use that JSON destination. Save uses atomic writes; unsaved edits prompt before replacing a map, closing the only window, or quitting. Invalid packages show an alert without replacing the current editor. Empty JSON files or MindNode packages display an explicit no-nodes state. Confirmed window close quits the app; Cancel keeps the map open.
