# MindMap (native editor prototype)

Build on macOS with Swift command-line tools: `bash build.sh`. Run with `open build/MindMap.app`.
No Xcode project, third-party dependencies, signing, or original application are required.

- A native toolbar is wired to New Child, New Sibling, Fold/Unfold, Fit Map, Undo and Redo; Fit Map reuses the same viewport-fit action used at launch and after successful document opens. An isolated visible/key native App AX-pressed its uniquely identified New Child toolbar button, confirming one selected child, a dirty title and native editing focus; the user also reported the sidebar/toolbar working in the earlier preview, but the new build's other toolbar buttons remain unverified by Agent GUI automation. The native Node menu exposes creation and detach commands. Tab: new child (or the first root when an opened map is empty); Return: new sibling; Option-Return: new sibling before; Option-Tab: insert a parent; Shift-Return: new main/root node. Ordinary sibling/parent insertion does nothing on roots (menu items are not yet disabled contextually).
- A native 180–320 pt outline sidebar shares the canvas tree, selected node, fold state and undo; View → Show/Hide Outline (Option-Command-S) collapses it. Selecting a row commits any active canvas edit first; successful document opens refresh the outline. Plain Return/Enter on a selected outline row uses the canvas editor; one isolated visible/key native App with the actual Node menu installed confirmed local Return edits the same node without adding a sibling. System VoiceOver and full sidebar keyboard behavior remain unverified.
- Type to edit the selected node through a native text field; double-click to replace its text, Escape to cancel editing. Chinese IME composition has not been verified in the final GUI build.
- Arrow keys: navigate visible nodes; Command-Up/Down: move the selected node among siblings; Command-Shift-D: detach the selected non-root node into a main/root node; Delete: remove a non-root node or an extra main root (the last root is protected); Option+period or Space: fold/unfold while the canvas has focus. While editing text, punctuation remains text input.
- Command-Z / Shift-Command-Z: model undo/redo. Drag empty canvas or the root to pan. Drag a **non-root** node at least 9 screen points: it and its visible descendants follow the grab point; over valid node/child-gap targets, siblings immediately make room without changing the real tree until mouse-up. A center-parent drop shows an accent rim; invalid release or Escape restores the original map. Pinch or Option-scroll to zoom. The user confirmed actual mouse drops in the earlier ghost-only preview; this new live reflow has render-level local-event checks but no post-change real-window/physical-mouse acceptance. Root reordering, free-position dragging and animated spring transitions are not implemented.
- Drawn nodes appear as labeled, selected-state accessibility buttons; press one to select and edit using the native text field. Their cached accessibility frames use the same live drag layout as the canvas, with layout-change notifications in an attached window; native VoiceOver has not been physically checked. Root ideas use 16pt semibold system text and branches 14pt medium; layout, drawing and inline editing share those metrics. Editing zooms to at least 0.8 when needed so the readable native field remains within the painted node; After editing ends, using Fit Map can return to lower zoom. View → Appearance offers persisted System (default), Light and Dark choices through native AppKit colors. The new build's real-window IME, appearance/contrast and editing-zoom feel remain unverified while the desktop is locked.
- File → Open Own JSON… (⌘O) opens editable `.mindmap.json` (a JSON array of roots); File → Open MindNode (Read-only)… (⇧⌘O) imports supported `.mindnode` directory packages. The MindNode picker keeps folders navigable, enables `.mindnode` directory packages and regular files while disabling unrelated files, and validates the chosen entry before accepting it. Both forms must contain the known v9 binary plist schema: `contents.xml` inside a directory, or the bytes of the regular file itself. Small ZIP archives receive an explicit unsupported-container alert; any document over 8 MiB is rejected before format inspection. The user reported that their own `.mindnode` file would not open, but its container type/version/error are unknown, so direct v9-file support does **not** establish that their file now imports; newer and compressed formats remain unsupported. Only text, tree structure and fold state are copied; styling, notes and attachments are **not** round-tripped. The source package is never edited. Save prompts for a **new** `.mindmap.json` after an import, even if another JSON file was previously open; subsequent saves use that JSON destination. Save uses atomic writes; unsaved edits prompt before replacing a map, closing the only window, or quitting. Invalid packages show an alert without replacing the current editor. Empty JSON files or MindNode packages display an explicit no-nodes state. Confirmed window close quits the app; Cancel keeps the map open.

In the earlier preview the user manually confirmed real mouse drop, unsaved protection, native JSON Open→edit→Save→reopen, sidebar and toolbar; drag still had ghost-only feedback then. The new source has pointer-coupled live reflow, edit-node containment and an Appearance menu, covered by offscreen RED→GREEN but not yet retested in a visible/key native window or by real hardware. G2 malformed-file picker rejection, G3 VoiceOver and other toolbar AX actions, and G4 full-window visual/IME checks remain open. Offscreen checks never close those gates. The layout is independent, text-aware geometry (up to 320 pt wide per node), not the original artwork. Opening and saving own JSON is size/ID/path checked; document titles compare current content against the last saved tree, so undoing back to it clears the unsaved marker. `Tests/RenderFixedSample.swift` renders the same synthetic ten-node map without opening windows; `dist/mindmap-closure-before.png` and `dist/mindmap-closure-after.png` show an earlier canvas, while `dist/mindmap-workbench-fit-after.png` renders the same fixed 10-node tree at 1200×850 with the current centered canvas and root typography. All are windowless canvas-only images, not the toolbar/sidebar or MindNode. `.mindnode` import remains **read-only**, with no original-format save or round-trip claim. The [gap baseline](docs/superpowers/specs/2026-10-20-mindmap-gap-baseline.md) and [read-only compatibility matrix](docs/superpowers/specs/2026-10-20-mindmap-readonly-compatibility.md) distinguish headless checks from GUI acceptance.
