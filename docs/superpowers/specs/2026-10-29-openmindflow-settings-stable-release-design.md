## 可信更新与渠道语义

- 更新渠道选项“稳定版”（默认）／“Beta”（明确主动选）；`checkUpdatesAutomatically` 仍默认关闭，不因为切换渠道而暗中联网。当前构建以 `CFBundleShortVersionString=0.6.0`、独立构建号标识新的稳定版，包内额外显式标记自身发行渠道 `stable`；Beta 构建只有真正发布时才使用 `beta` 标记，不能把 0.5 本地候选自动重新分类。
- GitHub Release 稳定版：tag `vX.Y.Z` 且 `prerelease=false`；Beta：tag `vX.Y.Z-beta.N` 且 `prerelease=true`。稳定渠道排除 Beta；Beta 渠道可选更新的 Beta 与更高同版本稳定终版，按照数值版本与预发行优先级而非 API 排序判定，不能降级。草稿、异常 tag、伪造 URL、意外域名或重定向继续拒绝；严格限制响应体与遍历条数，网络检查只返回官方 Release 链接，不静默下载／安装。
- 实际 check 请求改查可信仓库的 Release 列表，而不是 `/releases/latest`；明确区分请求中、有更新、无更新、网络失败、403/404 不可匿名访问和“当前尚无该渠道版本”。点击有更新才由用户确认在浏览器打开预期的可信页面。
- **私有仓库事实限制**：没有用户 token 时无法匿名查询真实私有 Release。当前私有期间，“现在检查”须显示清晰且可操作的“请在浏览器登录 GitHub 查看此仓库 Releases”及跳转入口；自动检查静默跳过不可访问，不将其伪称比对成功。只有在将来仓库经所有权人授权公开、或另有真正公开可信发布源后，才能对所有安装者保证联网版本比对；本轮不改仓库可见性。

## 验证与发布门槛

- RED/GREEN：导航条 Aqua/Dark Aqua 不透明填充与相邻区域像素差、横竖边界；设置三页布局在中英文、浅深色下不重叠、切换行为和现有偏好语义；Release 列表稳定／Beta 优先级、私有 403/404 与无版本区分、单次回调、恶意 URL／超体积／重定向。独立离屏 AppKit 原生窗口位图检查真实绘制，不能以无窗口纯模型单测冒充 GUI。
- 基线及相邻安全测试、独立只读评审、生产签名/DMG/ZIP 完整性、旧 0.4/0.5 哈希保持、用户运行文稿不接触。给用户独立预览供本人审阅外观与手感，合成窗口测试不等于真人视觉验收。
- 发布新稳定版 `v0.6.0` 到**现有私有 GitHub 仓库**，tag 和 Release 不替换历史预发布；附独立新构建包及 SHA-256。若仍是 ad-hoc 签名，Release 标题可以依用户决定叫“稳定版”，但正文必须显著告知未用 Developer ID、未公证、不提供自动安装或 Apple 官方安全验收；不得声称已经取得不存在的 LICENSE 或公开可下载。发布前如有未通过的核心测试或签名校验，不推送有缺陷工件或作错误状态声明。
