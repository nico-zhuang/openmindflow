# 独立 MindMap GUI 执行任务书｜2026-10-21

> 晚间真人操作反馈已推翻“无窗口通过即可继续视觉开发”的预期：子节点无法拖动、双击不能可靠重编辑；先执行[交互优先修订路线图](2026-10-21-real-gui-feedback-replan.md)中的 M1。下文“现状”保留最初基线，不代表当前 GUI 已通过。

## 目标与完成口径

目标是做出**独立、可日常整理想法**的 macOS 思维导图编辑器，逐步接近 MindNode 的清晰度和操作完成度；不以像素级复刻、原版素材或未经验证的格式兼容作为完成条件。每阶段都交付可运行程序、同一合成样例的可核对证据和未通过项。用户实际用鼠标/键盘完成任务优先于无窗口测试通过。

现状：Swift/AppKit 单窗口；自有 JSON 的有界读写、文本自适应布局、模型增删/折叠/撤销和无窗口八步旅程有回归测试。旧画布拖动只有“松手时落到另一个节点内部才改层级”：拖动期间节点不跟手，根节点拖动永不生效，空白落点无反馈。因此旧测试不是 GUI 拖动验收。自有 JSON 打开→修改→未保存→保存→重开的**完整 GUI 门槛仍未通过**。现有差距文档中“固定 170×44”是旧基线，已被文字尺寸感知布局取代。

## 方案取舍

- **采用：直接操作 → 文档闭环 → 原生界面框架 → 视觉打磨 → 可交付验收。** 先修用户眼前的“拖不动”，再建立可信的界面结构和视觉一致性。
- 不采用先换肤：工具栏和颜色无法使无反馈的拖动可用。
- 不采用一次性换 UI 技术栈：沿用已存在的 AppKit、`NSView`、`NSTextField`、`NSMenu`、原生面板、JSON 模型；新增第三方依赖和自造控件体系均须有无法复用的具体证据。

依赖：G1→G2→G3→G4→G5。G2 的人工原生选择器操作可以准备时并行，但未成功选择时不推进其 GUI 结论。每包完成前必须有失败再通过的最小可运行检查、全套无窗口回归和独立审阅；真实桌面焦点不可用时停止 GUI 动作，留待安全人工复验，不把环境阻碍写成通过。

## 共同安全边界与延期项

- `.mindnode` **仅只读导入 v9 目录包**；Save 只写自有 `.mindmap.json`。未知样式、备注、附件不往返；内部合成新副本代码未接入产品 GUI，不在本任务书开放原版格式保存。
- 不启动或恢复原版 MindNode，不查看用户私人导图、授权数据，不启用 `rea-mcp`；不向全局桌面发送键盘/鼠标事件，不猜测原生面板 XPC PID。
- 不为未经需求验证的自由定位、完整主题系统、云同步、附件和新 `.mindnode` 输出预设数据结构。自动排布树拖动与自由坐标拖动是不同产品能力；如后者成为明确需求，再单独设计 JSON 版本与迁移验收。
- GUI 验收只用自有、归属可验证的临时 App 及合成夹具；原生打开面板无法安全自动导航时由用户手选一次，系统只做绑定 PID 的有界 AX 观察。旧全局事件测试不得用作本任务书证明。
