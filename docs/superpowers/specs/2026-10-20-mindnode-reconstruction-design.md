# MindNode 交互兼容应用设计（待行为验证）

## 目标

在 `mindnode-reconstruction/` 新建独立 macOS 原生应用，优先重现本机 MindNode 2026.0.2 的日常节点编辑手感，再安全读取 `.mindnode` 文档。实现独立代码和视觉素材；不调用原版授权机制、不使用其私有资产。

## 证据与边界

- 原版为 arm64/x86_64 原生 macOS 应用；打包菜单的静态定义包括 Tab「New Child」、Return「New Sibling」，以及折叠、缩放、布局、聚焦等动作。这些菜单定义尚不证明运行时编辑行为。
- `Info.plist` 声明 `.mindnode` 的多个历史 UTI；真实磁盘格式、版本差异、附件及无损往返能力尚未验证。
- 所有原版交互实验只用临时创建的空白测试导图，避免读取或修改用户私人文档；测试文件和原版应用分离。禁止覆盖用户原件。

## 阶段一：操作手感

用最小原生 AppKit 画布承载节点、连接线、鼠标拖动、触控板缩放和平移，窗口和文本编辑使用平台原生行为。先验证并实现：Tab 新建子节点、Return 新建同级节点、编辑文本、方向键选择、Delete 删除、折叠/展开、撤销/重做、画布缩放和平移。静态快捷键只是候选；每项在临时导图中观察后再定稿。布局先采用确定性树布局，节点编辑后重新排版；不宣称原算法等价。

## 阶段二：文件兼容

先用临时文档调查原版文件容器及节点字段；安全只读导入有明确格式识别和错误提示。原格式写出必须对多类临时文档往返验证后再启用，未验证时保存为独立格式，绝不回写原文件或丢弃不认识的字段。

## 验收

原版与独立应用在同一临时测试步骤中对照：选中根节点 → Tab → 输入文字 → Return → 撤销 → 重做 → 折叠 → 缩放；比较节点层级、选区、编辑焦点与可见画布。文件测试至少涵盖空白、小树、特殊字符、带附件、损坏输入；导入失败不修改来源。操作系统权限无法获取时明确标记尚未验证，不以静态菜单代替运行时证据。

## 实现限制

本机有 Swift 6.2.1 命令行工具，但 `xcodebuild` 不可用；先以 `swiftc` 编译可运行的原生应用，正式签名和发布暂不纳入原型验收。无需添加第三方依赖。若测试发现原版采用不可安全复现的私有技术，以独立等效体验代替逐字节复制。
