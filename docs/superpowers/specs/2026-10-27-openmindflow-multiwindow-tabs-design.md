# OpenMindFlow 多窗口与可分离文稿标签设计

日期：2026-10-27。依据用户提出的 `⌘N` 新窗口、工具栏下浏览器式标签、右键切换横/竖显示、拖出独立窗口，以及此前展示的“每文稿独立会话＋每窗口标签容器”方案。本文为设计规格；尚不代表功能已经实现或获得实体拖拽验收。

## 目标与边界

- `⌘N` 在**新窗口**创建一个新未命名文稿；`⌘T` 在当前窗口创建新文稿标签；标签栏的 `＋` 与 `⌘T` 一致。窗口各自可有多个文稿标签。
- 标签栏位于原生工具栏**下方**：水平时在文稿上方，竖直时在左侧。右击标签栏空白处或标签打开“水平标签／垂直标签”菜单；切换只影响当前窗口，新的窗口继承最近一次偏好。活动标签显示名称及脏标记，切换后聚焦该文稿画布。
- 在本窗口拖动标签可排序；拖出标签栏并释放时建立独立窗口；拖至另一 OpenMindFlow 窗口的标签栏可合并。整个过程**转移相同的文稿会话对象**，不重新加载、不复制模型、不写磁盘，失败/取消保持来源标签和窗口不变。
- `.mflw` 字节格式、MindNode v9 有界保真来源包及受支持的导出范围保持 0.4.0 规则；不修改原 `.mindnode`、旧 JSON、旧 App/DMG/ZIP 或已有运行进程。仅产出新命名、`local.openmindflow.tabs.20261027` bundle ID、`0.5.0`/build `6` 的测试候选。原 MindNode 应用是否接受导出副本仍需独立人工验证。
- 不实现云同步、会话恢复、跨进程标签拖动、系统原生 NSWindow tab group 与文稿合并；不将离屏模拟拖动或程序化窗口尺寸当作真实鼠标体验通过。

## 取舍

1. **推荐：自定义标签栏＋文稿会话＋窗口协调器。**能同时提供工具栏下横/竖布局、拖出/拖回与现有 MindNode 来源档案的逐文稿保存规则；代价是必须自行处理焦点、辅助功能、拖动事务和关闭流程。
2. AppKit 原生窗口标签／`NSDocument`：系统管理部分窗口生命周期和横向标签，但竖向标签及精确的自定义标签位置/拖动行为无法简单等价实现，还会要求重写已验证的自定义二进制保存与来源包保护。此次不选。
3. 单窗口多个画布、拖出时复制模型：实现短期更快，但复制后会丢失或交叉污染撤销、未提交编辑、SHA/inode 与来源包，且存在误覆盖用户文件风险。此次明确拒绝。

## 架构与所有权

`DocumentSession` 为一个标签的唯一可变所有者：保留同一个 `MapModel`、`MapCanvas`、`MapOutlineView`、`StyleInspector`、工作区 `NSSplitViewController`，以及 `.mflw` URL、MindNodeArchive、最后读取的 SHA-256 和设备/inode、保存基准、dirty、Find 状态。`MapModel` 自带 per-instance Undo/Redo 快照；不得通过 `canvas.model =` 在切换标签时重建模型。文稿的加载/保存/导出使用现有 `NativeMapFile`、`MindNodeArchive` 操作及冲突检查；导入源永不自动成为保存目标。`commitPendingEditors` 归文稿会话，切换、关闭、保存前先处理标题及注释编辑；提交失败不切换或丢弃内容。

`WindowSession` 拥有一个 `NSWindow`、工具栏下的自定义 `TabStripView`、按序文稿会话、活动会话及横/竖偏好。标签栏是工作区外的兄弟视图，不侵入现有 outline/canvas/inspector 三栏；切换方向时保持窗口 frame 不变并补偿画布相对屏幕的根节点位置，避免原有侧栏跳动回归。窗口控制器路由本窗口标签菜单、`＋`、关闭/聚焦/拖放及工具栏操作；应用委托管理窗口集合、全局菜单、Finder 待打开 URL、全局语言和退出协调。菜单/工具栏命令必须从事件所属或当前 keyWindow 定位活动会话，不能读旧的 AppDelegate 单实例字段。

应用收到 Finder 的多个 `.mflw` URL 时，为每个不同文稿建立标签；通过同 FD 的设备/inode 身份发现已打开文件（含硬链接和常见大小写别名）时只聚焦原标签，不再建立可能互相覆盖的第二编辑器。URL 不可读取或文稿损坏时该项失败并说明原因，不更改其他已成功打开的会话。Open Map 和 Import MindNode 默认另开标签，保持当前未保存文稿；打开新独立窗口由 `⌘N` 执行。Find 搜索、选中节点与注释面板均绑定当前文稿，语言切换刷新**所有**窗口、标签、工具栏和工作区。

## 关闭、保存与拖拽不变量

- `⌘W` 关闭当前标签；若为窗口最后一个标签则关闭该窗口，而不是强制退出应用。关闭最后一个窗口后应用仍运行，`⌘N` 能再次创建窗口；此时 Finder 打开文件也能新建窗口。直接关闭多标签窗口和退出应用须逐一处理受影响的脏文稿。任何一次 Cancel、编辑提交失败或 Save 失败都阻止整个关闭/退出；已完成保存不回滚，但窗口和余下文稿保持可用。用户选择 Discard 也仅是预决策，须等所有待关文稿通过确认后才释放会话或断开工作区。
- 每个会话保存时只使用自身 URL、SHA、设备/inode 和来源包；原有 Save As 对硬链接、Finder 搬迁及复制回同字节新 inode 的拒覆盖保护在多窗口下原样生效。空白目标独占发布，外部修改明确报冲突，不因切换标签改变磁盘文稿。
- 拖动仅接受进程内临时会话令牌和明确的标签栏目标；画布保留媒体文件拖入处理，不接受标签令牌。先确认目标合法与会话归属，再提交数组/视图转移；仅在成功迁移最后一个标签后无提示关闭空来源窗口。无效 drop、Escape 或窗口消失时回滚原位置。拖拽过程中不调用 Save、Open、Export，也不修改 undo 栈。跨窗口 first responder/播放状态在迁移后重新绑定，不自动替换模型。
- 用户当前自定义“新建主节点”默认 `Shift-Return` 保留；从节点菜单及 `MapCanvas.keyDown` 同时移除硬编码 `⌘N` 新节点行为，避免 File 菜单新窗口被画布抢占。已有按钮“新建主节点”继续工作。
