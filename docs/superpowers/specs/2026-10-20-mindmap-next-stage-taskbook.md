## 目标与基线

目标是把第一阶段原型推进到**可独立日常编辑、可安全读取已验证范围内 MindNode 文档**的程度，而不是宣称原版源码、视觉或格式完整复刻。基线为 `feature/native-editor` 提交 `71675ac`；项目入口 `README.md`，原设计见 `docs/superpowers/specs/2026-10-20-mindnode-reconstruction-design.md`。截至本任务书编写，当前源码无界面构建、模型、布局、导入断言与 Info.plist 检查通过；最终静态修改后未复测 GUI，真实授权样本尚未在 GUI 中选入。现有 `dist/` 在工作树中未跟踪；不可把它当作已由本轮重新验收的发布包。

## Ask Five Pro 共识会议摘要

议题：下一阶段优先级、可验证交付与风险边界。模式：pro／共识。专家为基于公开资料构建的**模拟思维框架**，不是本人意见。

- **史蒂夫·乔布斯（产品与体验）**：「我会只抓一条完整的编辑旅程，而非铺开所有菜单。」理由是现有基本动作已有，真正缺口是选区、焦点与画布体验的连贯性；前提是目标为可用的独立工具，而非像素级复刻。与全面补功能的主张不同；盲区是未经真实对照不能说“与原版一样”。
- **张一鸣（证据与排序）**：「我会把观察、推断、未验证分开记录，再按影响排序。」理由是静态菜单、一次 GUI 记录和无界面断言证明的东西不同；前提是现有证据可追溯。与凭感觉改交互的路线不同；盲区是样本有限，不能推算全版本兼容。
- **Paul Graham（最小可用）**：「我宁可先把一条完整的编辑—保存—重开路径做好。」理由是能反复完成实际任务比功能清单长更有价值；前提是用户确实要独立编辑而非格式转换器。与广泛复刻不同；盲区是用户可能更重视某些未覆盖能力，执行后须以明确反馈调整。
- **Rob Pike（工程简洁）**：「我会保留原生平台输入与简单模型，只修有证据的断点。」理由是额外抽象和依赖扩大维护面；前提是现有架构尚能承载目标。与重写画布的想法不同；盲区是若性能或可访问性有可复现瓶颈，应允许针对性改造。
- **纳西姆·塔勒布（不可逆风险）**：「我反对任何可能写回私人原包的便利功能。」理由是收益是省一次另存，损失可能是不可恢复的源文件；前提是只读导入仍满足这阶段目标。与追求双向兼容不同；盲区是只读不等于所有输入都安全，异常样本和路径仍需测试。

**判定：条件共识。** 在“独立日常工具＋安全只读导入”的目标下，先证据对照、再补核心体验、最后扩展验证；是否追求原版高度一致属于另一决策。保留分歧：产品视角希望尽早观察实际手感，风险视角反对未经明确请求而启动原版／反复 GUI 操作。解决方式：默认静态及无界面验证，GUI 对照设为单独确认的验证项，不以缺失的 GUI 证据冒充完成。

## 三步工作与阶段门

### 第一步：建立差距基线（只读，无界面优先）

- 核对代码、现有设计、已保存测试记录与打包静态证据；按“已观察／仅静态推断／尚未验证”归类基础编辑、布局、选区焦点、文件行为。
- 形成一页按影响排序的差距清单及一条核心编辑旅程的验收脚本：根节点 → 子节点 → 文本 → 同级 → 撤销/重做 → 折叠 → 缩放 → 保存 → 重开。
- **交付/通过条件：**每条待改项有证据来源和可复验结果；没有原版运行时证据的交互不得标注为“原版等价”。本步不启动 GUI。若要实际界面对照，须先取得用户提出的具体界面验证需求，再采用单次、受控的临时空白图测试；不循环开窗口。

### 第二步：补齐核心日常体验（确认第一步优先级后）

- 仅针对第一步证实的高影响问题修改编辑、选区/焦点、可见布局、平移缩放、输入与可访问性；不为了“看起来功能多”堆菜单。
- 保持独立 AppKit 工程及自有视觉，保留已有 `.mindmap.json` 的保存边界、原子写入与未保存确认。
- **交付/通过条件：**核心编辑旅程在模型/布局/文件的无界面检查中可重复通过；有改动的非平凡逻辑留最小回归断言；构建通过。对 IME、手势或视觉手感等无法由无界面检查证明的内容，诚实列为待具体 GUI 验证，不据此声称等价。

### 第三步：扩大只读兼容与交付验收

- 在用户授权范围内，仅对 `.mindnode` 目录包进行只读解析与格式分组验证；覆盖可取得的空白、小树、特殊字符、包含备注/附件的输入及损坏输入。缺少某类授权样本时记为未验证，不造“全覆盖”结论。
- 检查导入失败不替换当前导图、成功导入另存 `.mindmap.json`、源文件前后哈希不变；报告只记录结构、统计与哈希，不记录私人节点正文。
- **交付/通过条件：**无界面构建及回归通过；样本兼容矩阵注明版本、结果和限制；重新打包并核验产物身份；README 与实际能力一致。任何需要 GUI 操作才可判定的条目保持“未做 GUI 验证”，不凭 CLI 推断界面成功。

## 不做、保护与停止线

- 不修改、覆盖、安装到原版 MindNode；不改授权原始导图；不在代码、日志、报告里记录私人节点正文。
- 不启用全局 `rea-mcp`；确有静态逆向必要时仅用已安装的 `rea` CLI。不主动循环启动应用或做 GUI 自动化。
- 本轮不做 `.mindnode` 写出、无损样式/备注/附件往返、原版视觉素材复制、像素级或运行时完全等价、正式签名/公证发布；这些是**独立可选阶段**，须另立目标和验收条件。
- 发现源文件有写入风险、导入可能静默丢失而被误称无损、或验证需要超出授权范围时立即停止该项并如实报告；不以多数意见覆盖这一安全边界。
