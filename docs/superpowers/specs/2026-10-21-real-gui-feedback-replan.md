# 独立 MindMap：真实 GUI 反馈后的下一阶段路线图｜2026-10-21

## 决策与现状

**下一步只攻“能真正操作节点”，停止继续叠加工具栏、配色和宣传截图。** 用户在实际窗口观察到：主节点可以拖动，子节点无法拖动；双击似乎不能重新编辑文案。整体体验距离目标软件仍很远。这是优先级高于现有九项无窗口断言的产品反馈；不能因 `MapCanvas.mouseDown/Dragged/Up` 直接调用测试通过而宣布交互完成。

目前代码中根节点拖动设计为**平移画布**，不是根节点自由摆放；因此“主节点可以拖动”记录为用户观察，不先替用户解释为节点位置发生了变化。此前新预览版 `NSWorkspace` 启动返回 PID `90227`，随后按该 PID 查询未见存活进程，故**无法确认用户实际操作的是哪个构建**。这不否定操作反馈，只要求先锁定运行版本，再归因或验收。旧 PID `73855` 的内容仍不明，禁止据此读取、结束或清理旧进程/夹具。

### 路线取舍

1. **推荐：沿用现有 AppKit，先确认版本和真实事件路由，再修一条共享的节点命中—选择—编辑—拖动路径。** 最小改动能直接回答两项失败是否同因；每个修复都要在真实窗口重新操作。
2. 暂不先做视觉换肤：不会让收不到的双击、子节点拖动恢复，反而遮蔽缺陷。
3. 暂不换 SwiftUI/新画布引擎：现有模型、撤销、自有 JSON 与 AppKit 控件可复用；只有在事件链被证据证明无法可靠修复时才重新评估技术栈。

| **T1 节点命中、选中与重编辑** | 从真实鼠标点位追踪 `NSWindow → NSSplitViewController → MapCanvas/内联 NSTextField`：核对画面卡片、局部坐标与实际命中 UUID，单击选中、双击进入字段、编辑后提交；必要时核查 `MapOutlineView` 的焦点交接。主要是 `Sources/App.swift`，辅以 `Tests/CanvasCommandTests.swift`、`Tests/OutlineWorkbenchTests.swift`。 | 依次双击根和两个子节点，每个都出现可输入字段；输入、失焦、再次双击能改**同一个**节点，其他节点文案不变；Escape 的取消与一次撤销可预测。若单击/双击仍落在空白或字段上，停止去做拖动/美化，先修共用事件入口。 |
| **T2 子节点直接拖动** | 在 T1 已证实的命中路径上检查抓取阈值、编辑字段是否抢鼠标、移动时的跟手预览、有效落点判定、松手的一次 `MapModel.moveNode` 和撤销；复用现有 `canMoveNode`，不在每个调用方各加补丁。主要是 `Sources/App.swift` 与既有模型/画布断言。 | 两个不同子节点各拖到合法目标中央一次：拖动中可见跟手节点和有效目标，松手后层级改变，⌘Z 恢复；拖到空白/自身不改树。抓住根节点仅平移画布，除非以后单独批准自由定位。任一步失败便留在本任务，不以事件合成通过代替真人操作。 |

| **T4 工作台与视觉输入** | 只在 T3 通过后，实际检查大纲、工具栏与画布共用选择/撤销、窄窗布局、30 节点长标题、中文 IME、浅/深色对照和键盘/VoiceOver。主要是 `Sources/App.swift`、`Sources/MapOutlineView.swift` 和真实窗口截图；继续沿用原生组件，不先造样式架构。 | 一张合成图可从大纲和画布一致地选中/编辑，在浅深色窗口中不裁文字、中文组合输入不丢字；风格/主题、自由摆放、附件或写回 `.mindnode` 暂不立项，由 M1 与 T3/T4 实测差距决定。 |

T1/T2 的具体修复**尚未确定**。先记录有限、可删除的诊断证据：仅在自有合成窗口记录视图类、事件局部坐标、命中节点 UUID、clickCount、firstResponder 和手势状态；不记用户文案、不投递全局事件。最小断言保持 RED→GREEN；隐藏且非 key 的 `NSWindow.sendEvent` 曾不能派发鼠标，不能再当作实际窗口验收。每个任务均需全套无窗口回归与独立代码审阅，**再由真实鼠标验证**。

## 最近一个里程碑：M1「节点基本可用」

**范围仅 T0＋T1＋T2，不以视觉接近 MindNode 为此里程碑的放行条件。** 在身份可确认的新版 App、全新一根两子合成图上，用户连续完成三轮：选中并双击修改一个子节点→提交后再次双击修改→把该子节点拖到另一个合法目标→看到实时预览及层级变化→⌘Z 还原。三轮中不得把子节点拖动误判成整张图平移，不得误改其他节点；无效投放保持原树。记录真实窗口版本、前/后树、未保存状态和失败画面；一项失败就不宣布 M1 通过。

M1 通过后才制定下一段“文件工作闭环”的实施计划；完成 T3 文件闭环及 T4 真实窗口走查后才讨论高完成度版本交付。现有 [G1–G5 任务书](2026-10-21-independent-mindmap-gui-taskbook.md)保留为历史执行记录，但其 G1/G2/G3/G4/G5 **均不得因代码或截图存在而勾选**。下一步等待用户认可此路线图后，另写 T0–T2 的 RED/GREEN 实施计划；**本次不改生产代码、不启动新的 GUI、不清理旧进程。**
